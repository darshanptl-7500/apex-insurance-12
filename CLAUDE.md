## Onboarding context (hand-maintained — see `.planning/PROJECT.md` and `.planning/RISKS.md` for full detail)

Apex Insurance is a demo/training **London Market Underwriting Workbench**: submissions → quotes → bind → policy → claims, plus documents, workflow tasks, broker/insured CRM, and MI reporting. It is explicitly **not** the system of record — `ApexInsurance.Data.OpenBox` is a deliberate in-process **stub** of a legacy policy admin system ("Open Box"), not a real integration. Don't "fix" it into a real integration by mistake.

**Do not treat the following as safe patterns to copy or leave in place if this code is ever pointed at a real environment:**
- `src/ApexInsurance.Api/appsettings.json:3` has a live-looking, committed SQL Server password (README acknowledges it needs rotation if shared).
- `ApexInsurance.Security/DemoTokenService.cs` issues unsigned Base64 "tokens" — there is no real signature validation anywhere; treat all auth in this repo as demo-only.
- `AuthService.cs` silently accepts the literal password `Password1!` for any user without a stored hash.

Schema is managed by hand-written SQL in `database/*.sql`, **not** EF Core migrations (despite a stale comment in `01_CreateSchema.sql` saying "EF6" — the code actually uses EF Core 10).
